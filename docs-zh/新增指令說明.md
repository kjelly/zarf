# Zarf 新增指令說明

本文檔說明 `v0.35.0` 新增的兩個子指令：`zarf install` 與 `zarf extract`。

---

## zarf install

### 功能說明

`zarf install` 用於**依序部署多個 Zarf 包**。每個包的部署流程等同於 `zarf package deploy --confirm`，表示所有互動式提示都會被跳過（自動確認）。

### 使用方式

```bash
zarf install <package_source> [package_source ...] [flags]
```

**別名**：`i`

### 範例

```bash
# 部署單個包
zarf install zarf-package.tar.zst

# 依序部署多個包
zarf install package1.tar.zst package2.tar.zst package3.tar.zst

# 部署並指定變數
zarf install package1.tar.zst package2.tar.zst --set-variables DOMAIN=example.com

# 部署並指定要包含的元件
zarf install package.tar.zst --components frontend,database
```

### Flags

| Flag | 說明 |
|------|------|
| `--adopt-existing-resources` | 接管現有的 K8s 資源 |
| `--components` | 指定要部署的元件（逗號分隔） |
| `--connected` | 不推送 images/repos，僅標記資源 |
| `-f, --force-conflicts` | 強制 Helm 取得衝突欄位所有權 |
| `-k, --key` | 公鑰路徑（用於簽名驗證） |
| `--namespace` | 覆寫部署的命名空間 |
| `--oci-concurrency` | OCI 操作的併發數 |
| `--retries` | 重試次數 |
| `--set-variables` | 設定部署變數（KEY=value） |
| `--set-values` | 設定 values（key.path=value） |
| `--timeout` | 健康檢查與 Helm 操作的逾時時間 |
| `--values` | 指定 values 檔案（可多次指定） |
| `--verify` | 強制驗證簽名 |
| `--skip-version-check` | 忽略版本需求檢查 |

## zarf extract

### 功能說明

`zarf extract` 用於**從 Zarf 包中提取 Helm charts、values 檔案及容器鏡像**，方便手動部署或離線使用。提取後會生成一個 `install.sh` 腳本，內含 `helm install` 指令範本。

### 使用方式

```bash
zarf extract <package_source> [package_source ...] [flags]
```

### 範例

```bash
# 提取單個包（預設輸出至 ./zarf-extracted/）
zarf extract zarf-package.tar.zst

# 指定輸出目錄
zarf extract zarf-package.tar.zst -o ./my-charts

# 提取多個包
zarf extract package1.tar.zst package2.tar.zst -o ./output

# 跳過提取容器鏡像
zarf extract zarf-package.tar.zst --no-images

# 提取並指定變數（用於解析 ###ZARF_VAR_*### 模板）
zarf extract zarf-package.tar.zst --set-variables DOMAIN=example.com
```

### Flags

| Flag | 說明 |
|------|------|
| `-o, --output` | 輸出目錄（預設：`zarf-extracted`） |
| `--set-variables` | 設定變數（KEY=value），用於解析包中的 `###ZARF_VAR_*###` 模板 |
| `--no-images` | 跳過提取容器鏡像 |

### 輸出目錄結構

```
<output-dir>/
├── <package-name>/
│   ├── images/                          # Docker tar 格式的容器鏡像（docker save 相容）
│   │   ├── docker.io_library_nginx_1.25.tar      # 每個鏡像一個檔案
│   │   ├── ghcr.io_myorg_myapp_v1.0.0.tar
│   │   └── ...
│   ├── <component-name>/
│   │   ├── charts/
│   │   │   └── <chart-name>-<version>.tgz    # Helm chart 壓縮包
│   │   └── values/
│   │       └── <chart-name>-<version>-values.yaml  # 合併後的 values
│   └── install.sh                     # 可執行的安裝腳本
```

### install.sh 內容範例

```bash
#!/usr/bin/env bash
# Generated by zarf extract
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# Container images are available as Docker tarballs in the images/ directory.
# To load and push an image:
#   docker load -i images/<image-file>.tar
#   docker tag <image-name>:<tag> <registry-url>/<image-name>:<tag>
#   docker push <registry-url>/<image-name>:<tag>
#

# Component: frontend, Chart: nginx
helm install frontend \
  "$SCRIPT_DIR/frontend/charts/nginx-15.0.0.tgz" \
  --namespace frontend \
  --values "$SCRIPT_DIR/frontend/values/nginx-15.0.0-values.yaml" \
  --create-namespace
```

### 變數處理

`zarf extract` 會自動解析以下模板：
- `###ZARF_VAR_*###` — 替換為預設值或 `--set-variables` 指定的值
- `###ZARF_CONST_*###` — 替換為常數值
- `###ZARF_PKG_TMPL_*###` — 替換為套件層級模板值

以下模板**不會**被解析（需要 K8s 叢集資訊）：
- `###ZARF_REGISTRY###`
- `###ZARF_GIT_SERVER###`
- `###ZARF_AGENT_IMAGE###`

### Values 合併順序

最終的 Helm values 依照以下優先順序合併：

1. Chart 內建的 `values.yaml`（`.tgz` 中）
2. Zarf 包中的 values 檔案（`###ZARF_VAR_*###` 已解析）
3. `ZarfChartVariable` 映射（Zarf 變數 → Helm value path）
4. `ZarfChartValue` 映射（Zarf package-level value → Helm value path）

## 鏡像推送方式

提取的容器鏡像位於 `images/` 目錄（Docker tar 格式，每個鏡像一個檔案）。有以下幾種方式可將鏡像載入目標環境：

### 使用 Docker

```bash
# 載入單個鏡像
docker load -i images/<image-file>.tar

# 標記並推送到目標 registry
docker tag <image-name>:<tag> <registry-url>/<image-name>:<tag>
docker push <registry-url>/<image-name>:<tag>

# 批量處理所有鏡像
for tar in images/*.tar; do
  docker load -i "$tar"
done
```

### 使用 Podman

```bash
# 載入單個鏡像
podman load -i images/<image-file>.tar

# 標記並推送
podman tag <image-name>:<tag> <registry-url>/<image-name>:<tag>
podman push <registry-url>/<image-name>:<tag>
```

### 使用 Skopeo

```bash
# Docker tar → Docker registry
skopeo copy docker-archive:images/<image-file>.tar docker://<registry-url>/<image>:<tag>
```

## 與 zarf package deploy 的差異

| 特性 | `zarf package deploy` | `zarf install` | `zarf extract` |
|------|---------------------|----------------|----------------|
| 需要 K8s 叢集 | ✅ | ✅ | ❌ |
| 互動式確認 | 可選（`--confirm`） | ❌（始終確認） | N/A |
| 多包依序部署 | ❌ | ✅ | ❌ |
| 提取 charts/values | ❌ | ❌ | ✅ |
| 提取容器鏡像 | ❌ | ❌ | ✅ |
| 生成 helm install 指令 | ❌ | ❌ | ✅ |
| 離線使用 | 受限 | 受限 | ✅ |

## 離線工作流程範例

```bash
# 1. 在有網路的機器上，提取 Zarf 包內容
zarf extract zarf-package.tar.zst -o ./offline-pkg

# 2. 將整個目錄複製到離線環境（USB、DVD 等）

# 3. 在離線環境中，載入容器鏡像
docker load -i ./offline-pkg/zarf-package/images/<image-file>.tar

# 4. 標記並推送到目標 registry
docker tag <image-name>:<tag> <registry-url>/<image-name>:<tag>
docker push <registry-url>/<image-name>:<tag>

# 5. 修改 install.sh 中的 registry URL（如需要）

# 6. 執行安裝腳本
cd ./offline-pkg/zarf-package
./install.sh
```
